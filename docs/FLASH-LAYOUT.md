XR1710G — Flash 完整布局图（原厂 vs ImmortalWrt）
========================================================================
芯片: Winbond W25N04KVZEIR, SPI NAND, 512 MiB
实测校验: 原厂分区表合计 = 446 MiB，与 512 MiB 芯片吻合

────────────────────────────────────────────────────────────────────────
原厂布局（来自 ECNT> mtd）
────────────────────────────────────────────────────────────────────────
  名称            起始          结束          大小        内容
  bootloader      0x00000000    0x00200000    2.0 MiB     BL1/BL2/BL31/U-Boot + 证书
                                                          ├ 0x000800  FIP 头 (AA640001)
                                                          ├ 0x000C00  BL1 代码
                                                          ├ 0x004420  BL2 记录 A
                                                          ├ 0x00FE08  BL2 记录 B
                                                          ├ 0x01BC00  签名块 + Tb-FW 证书
                                                          ├ 0x01F800  BL31 记录
                                                          ├ 0x029C00  U-Boot 记录
                                                          └ 0x080000  工厂默认 uenv
  uenv            0x00200000    0x00400000    2.0 MiB     运行时环境变量
  dsd             0x00400000    0x00600000    2.0 MiB     出厂数据（MAC/序列号/WiFi）
                                                          ├ 0x0000-0x0158  文本键值
                                                          ├ 0x1000-0x23DA  PKCS#7 encryptedData ×3
                                                          └ 0x5000-0x5D72  校准/数据段
  tclinux         0x00600000    0x04600000   64.0 MiB     主系统镜像
    ├ kernel      0x00600000    (伪分区，与 tclinux 同址)
    └ rootfs      0x00600000    (伪分区，与 tclinux 同址)
  tclinux_slave   0x04600000    0x08600000   64.0 MiB     备用系统镜像（A/B 双备份）
    ├ kernel_slave 0x04600000   (伪分区)
    └ rootfs_slave 0x04600000   (伪分区)
  system          0x08600000    0x1BE00000  312.0 MiB    数据/应用分区
  (保留区)        0x1BE00000    0x20000000   66.0 MiB     坏块管理 / 预留，不要写

────────────────────────────────────────────────────────────────────────
ImmortalWrt 当前布局（你的备份，来自 /proc/mtd）
────────────────────────────────────────────────────────────────────────
  名称            起始          结束          大小
  vendor          0x00000000    0x00600000    6.0 MiB      ← 原 bootloader+uenv+dsd 全包进来
  chainloader     0x00600000    0x00700000    1.0 MiB
  ubi             0x00700000    0x1A700000  400.0 MiB      ← 原 tclinux 两套合并
  reserved_bmt    0x1A700000    0x1BE00000   23.0 MiB      坏块表 + 预留

  对照结论：
    · ImmortalWrt 的 vendor(0x0-0x600000) 正好覆盖原厂三区，
      所以 mtd0 备份里 0x400000 就是原厂 dsd、0x200000 就是原厂 uenv —— 位置完全对得上
    · 原厂 tclinux + tclinux_slave = 128 MiB，ImmortalWrt 并成 400 MiB 的 ubi
    · 原厂有 A/B 双镜像，回滚余量大；ImmortalWrt 只有单一 ubi

────────────────────────────────────────────────────────────────────────
刷写时的关键边界（务必记住）
────────────────────────────────────────────────────────────────────────
  · 0x000000-0x200000  bootloader  ← 只能写这 2 MiB，写超会踩 uenv
  · 0x200000-0x400000  uenv        ← 只有 1 KiB 有效数据，其余是填充
  · 0x400000-0x600000  dsd         ← MAC/序列号/WiFi，32 KiB 写入足够
  · 0x600000 起        原厂内核    ← bootcmd 就是从这里读:
                                      flash read 0x600000 0x100000 $loadaddr
  · 0x1BE00000 之后    不要碰      ← 坏块/预留区

  整块写 bootloader 时的安全命令：
      flash erase 0x0 0x200000
      flash write 0x0 0x200000 0x81800000      # filesize 必须是 0x200000

────────────────────────────────────────────────────────────────────────
两个布局的互换关系
────────────────────────────────────────────────────────────────────────
  原来          现在(ImmortalWrt)   说明
  bootloader    含在 vendor 内       偏移不变，仍在 0x0
  uenv          含在 vendor 内       偏移不变，仍在 0x200000
  dsd           含在 vendor 内       偏移不变，仍在 0x400000
  tclinux       ubi 的一部分         ImmortalWrt 用 ubi 卷代替裸分区
  tclinux_slave —                    被合并进 ubi，不再单独存在
  system        ubi 的一部分
  保留区        reserved_bmt         起始从 0x1A700000 起（被往前挪了）

  => 三个关键分区（bootloader/uenv/dsd）偏移在两个布局里**完全相同**，
     所以按 0x0 / 0x200000 / 0x400000 刷写，两种固件下都适用。

────────────────────────────────────────────────────────────────────────
DTS 确认（官方 airoha en7581 分区表，供交叉验证）
────────────────────────────────────────────────────────────────────────
  OpenWrt 上游 target/linux/airoha 的 an7581 DTS 里，固定分区名就是
  bootloader / uenv / dsd / tclinux / tclinux_slave / system，
  与本机 ECNT> mtd 输出一致 —— 说明这是 Airoha 参考设计的标准布局，
  其他 AN7581 机型（如 XG2010G）大概率也是同一套偏移。
