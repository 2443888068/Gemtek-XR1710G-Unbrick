XR1710G — 没有原厂备份时怎么救活（完整流程）
========================================================================

适用场景：flash 被擦空 / 换了新芯片 / 二手砖机 / 原厂 mtd0 丢了
前提：只要 CPU 和串口是好的，Airoha BootROM 在芯片里，就能救。

────────────────────────────────────────────────────────────────────────
第一步：恢复 bootloader（不需要任何备份）
────────────────────────────────────────────────────────────────────────
  用 X 模式两阶段文件，这两个文件包含了完整的 BL1 / BL2 / BL31 / U-Boot
  和全套证书，与设备原本的引导链一致：

   1_stage1_preloader.bin        126,972 B
   2_stage2_bl31_uboot.bin       507,904 B

  操作：
   1. 断电，按住 RESET 上电，串口 115200
   2. 按 X（或 x），终端出现 CCCCC
   3. XMODEM 发送 1_stage1_preloader.bin   → 自动重启
   4. 再次断电，按住 RESET 上电
   5. 提示 Press x to load BL31 + U-Boot FIP 时按 x
   6. XMODEM 发送 2_stage2_bl31_uboot.bin  → 自动重启

  完成后 bootloader 区段（flash 0x0-0x200000）就是完好的，
  设备能进 U-Boot 命令行。

────────────────────────────────────────────────────────────────────────
第二步：生成 DSD 和 uenv（不需要任何备份）
────────────────────────────────────────────────────────────────────────
  打开 XR1710G_一键生成_无备份版.html，什么都不用改，直接点生成。
  它会下载 dsd_xxxx.bin 和 uenv_xxxx.bin。

  生成的内容：
    wan_mac / lan_mac      按 OUI 00:58:28 生成，单播 + 全局唯一 + 连号
    serial_number          XR1710G + 10 位数字
    wifi_ssid / 密码 / WPS  随机生成（会显示在页面上，请记下）
    uenv 环境变量           内置默认集合（含正确的 bootcmd）

  同型号多台设备：把「生成台数」设成 N，MAC 自动连号不重复，每台一套文件。

────────────────────────────────────────────────────────────────────────
第三步：写进 flash
────────────────────────────────────────────────────────────────────────
  把 dsd_*.bin 和 uenv_*.bin 传到设备（TFTP 或串口），然后：

    # DSD -> flash 0x400000
    flash erase 0x400000 0x8000
    flash write 0x400000 0x8000 0x81800000

    # uenv -> flash 0x200000
    flash erase 0x200000 0x400
    flash write 0x200000 0x400 0x81800000

    reset

  之后系统（ubi）用官方 sysupgrade 镜像刷即可。

────────────────────────────────────────────────────────────────────────
必须知道的限制（诚实说明）
────────────────────────────────────────────────────────────────────────
  1) WiFi 射频校准数据无法重建
     每台机器的校准值是出厂逐台测量后写进 DSD 的（在 DSD 的 0x5000 段），
     和这台机器的射频前端一一对应。没有原厂 DSD 就拿不到。
     后果：能开机、WiFi 大概率能连，但发射功率/接收灵敏度不达标，
     5GHz 有可能起不来。想彻底解决只能：
       · 找同型号正常机器，把它的 DSD 整段读出当模板（改掉 MAC/序列号）
       · 或用原厂产线工具重新校准

  2) DSD 里 0x1000 段是三个 PKCS#7 encryptedData 加密容器
     （PBES2 + PBKDF2 + AES-128-GCM，逐台 salt/IV 都不同）。
     它**不是签名**，不参与校验；但没有口令解不开，本流程生成的 DSD 该段为空。
     密文是否与设备绑定（口令是否含本机 MAC/OTP 密钥）静态分析看不出来，
     只能实测 —— 方法见 DSD加密段说明.txt。

  3) bootloader 区段里没有出厂默认 DSD
     已全盘确认：整片 flash 里只有 0x400000 一处 DSD。
     所以不存在"从别处抄一份默认值"的可能。

  4) 序列号是编造的
     如果设备还在保修/运营商体系内，序列号对不上可能影响售后。
     能查到原序列号（机身标签）就填进去。

────────────────────────────────────────────────────────────────────────
推荐做法（给别人修机器时）
────────────────────────────────────────────────────────────────────────
  · 先问对方有没有原机备份，有的话优先用备份（MAC/校准都是原装的）
  · 没有备份，但能找到同型号正常机器：
      用 XR1710G_DSD生成器.html 的「载入现有 DSD」读那台机器的 DSD，
      然后只改 wan_mac / lan_mac / serial_number，其余（含校准段）保留
  · 什么都没有：用无备份版生成，接受 WiFi 性能可能不达标
