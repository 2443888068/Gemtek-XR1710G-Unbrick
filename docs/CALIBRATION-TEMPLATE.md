XR1710G — 含校准的 DSD 生成器（给别人修机器用）
========================================================================

一、这个工具解决什么问题
------------------------------------------------------------------------
  场景：别人的 XR1710G 把 dsd 分区搞炸了，机器没有 MAC、没有序列号、
        WiFi 校准也没了，而且对方没有任何备份。

  做法：把一台正常 XR1710G 的 DSD 当"底座"，清掉里面的身份信息，
        只保留二进制结构 + WiFi 校准段，然后按用户填的参数重新写入文本段。

  结果：生成的 DSD 同时具备
        · 正确的 MAC / 序列号 / WiFi 名称密码（文本段，按输入生成）
        · 同型号的 WiFi 校准数据（二进制段，原样保留）
        · 完整的尾部结构标记

二、校准模板怎么做的（脱敏清单）
------------------------------------------------------------------------
  源：本机 XR1710G 的原厂 DSD（来自 mtd0 的 0x400000）

  处理：
    0x0000-0x0158  文本段        -> 全部覆盖为 0xFF（清除 MAC/序列号/密码）
    0x1000-0x23DA  加密段        -> 全部覆盖为 0xFF（原厂 PKCS#7 ×3，见第四节）
    0x2500-0x5D71  二进制/校准段 -> 原样保留
    0x5D72-0x6C66  尾部数据段    -> 原样保留

  脱敏核对（模板里搜索本机隐私，全部 0 命中）：
    MAC 字符串 "58:28"        0 次
    MAC 二进制 00 58 28       0 次
    序列号 XR1710G0000000000  0 次
    WiFi 口令前缀 "Bright"    0 次
    "admin" / "Gemtek"        0 次

  模板文件：dsd_template_cal_only.bin   27,750 字节
            sha256 ce6fd734facaa4936eb146af311c62b9...
            （已内嵌进 HTML，使用时不需要单独的文件）

三、怎么用
------------------------------------------------------------------------
  打开 XR1710G_DSD生成器_含校准.html
    · 默认什么都不用改，直接点"生成 DSD + uenv"
    · 或者填对方提供的 MAC / 序列号（有原机标签就用原值）
    · "生成台数"填 N 可批量，MAC 自动连号不重复

  写入（同 Flash布局图.txt）：
    flash erase 0x400000 0x8000
    flash write 0x400000 0x8000 0x81800000     # DSD
    flash erase 0x200000 0x400
    flash write 0x200000 0x400 0x81800000      # uenv

四、关于 0x1000 加密段
------------------------------------------------------------------------
  原厂该段是三个 PKCS#7 encryptedData 容器：
    ContentInfo(pkcs7-data) > SEQUENCE > encryptedData ×3
      每个: PBES2 > PBKDF2(salt 8B + HMAC-SHA256) + AES-128-GCM
      salt/IV 三块各不相同，密文也各不相同

  它不是签名、不参与校验。但**没有口令解不开**，所以：
    · 本工具默认把它留空（0xFF）
    · 如果实测发现设备必须要它，那就不能只用校准模板了，
      得改用整份原厂 DSD 当底座（只改文本段）——
      参考 XR1710G_DSD生成器.html 里的「载入现有 DSD」功能

五、校准到底通不通用？（必须实测一次）
------------------------------------------------------------------------
  支持通用的理由：
    · 同型号硬件设计、射频前端、天线都相同
    · 校准表结构（0x5000 段的表项）呈周期性，看起来是"按信道/速率查表"，
      不是逐台随机值

  风险：
    · 若原厂在校准里嵌了 MAC 或 OTP 绑定信息，换机后可能被忽略或不生效
    · 加密段（若设备确实需要）可能正是做这个绑定的

  建议的实测流程（第一次给别的机器用时做一次）：
    1. 用本工具生成 DSD，写入对方机器
    2. 开机，串口看有没有校准相关报错
    3. 进系统后：
         iw dev            # 看 WiFi 接口 MAC 是否正确
         iw phy            # 看发射功率是否合理（不应是 0 或异常小）
         iw dev wlan0 scan # 看能否扫到 AP
    4. 若一切正常 -> 校准通用，这套工具可以放心用
       若报错/扫不到 -> 校准绑定了设备，只能找原厂或产线工具

六、文件清单
------------------------------------------------------------------------
  XR1710G_DSD生成器_含校准.html     ← 主工具（内嵌校准模板，18 KB 单文件）
  dsd_template_cal_only.bin         脱敏后的校准模板（备用，方便核对）
  Flash布局图.txt                   分区表与写入偏移
  DSD加密段说明.txt                 0x1000 段的完整解析与跨设备判定方法
  1_stage1_preloader.bin            X 模式第一阶段
  2_stage2_bl31_uboot.bin           X 模式第二阶段

七、给别人修机器的完整顺序
------------------------------------------------------------------------
  1. X 模式刷 1_stage1_preloader.bin  → 重启
  2. 按住 RESET 上电，按 x → 刷 2_stage2_bl31_uboot.bin → 重启
  3. 用本工具生成 dsd_*.bin / uenv_*.bin
  4. 写入 0x400000 / 0x200000
  5. 重启，按第五节的实测流程确认 WiFi
  6. 正常的话，按对方需要刷系统镜像（ubi）
