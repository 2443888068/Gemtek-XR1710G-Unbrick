XR1710G — DSD 里那段 ASN.1 到底是什么？能不能跨设备用？
========================================================================

一、先纠正：那不是签名，是加密数据容器
------------------------------------------------------------------------
  DSD 0x1000 段的完整类型（逐字段解析结果）：

    ContentInfo
      └─ contentType = PKCS#7 data           (1.2.840.113549.1.7.1)
         └─ content
            └─ SEQUENCE
               ├─ encryptedData #1          (1.2.840.113549.1.7.6)
               │    └─ PBES2                (1.2.840.113549.1.5.13)
               │         ├─ PBKDF2          (1.2.840.113549.1.5.12)
               │         │    ├─ salt  8 字节   ← 三个容器各不相同
               │         │    ├─ iter  (8 字节 INTEGER)
               │         │    └─ prf = HMAC-SHA256 (1.2.840.113549.2.9)
               │         ├─ AES-128-GCM     (2.16.840.1.101.3.4.1.43)
               │         │    └─ IV 16 字节
               │         └─ ciphertext
               ├─ encryptedData #2  （同样结构，salt 不同）
               └─ encryptedData #3  （同样结构，salt 不同）

  三个容器：
    #1 @DSD+0x1000  salt=86b46ffcafe3e730  IV=7399869393a27df6868f1453004af787
    #2 @DSD+0x1748  salt=f5f8afaa2233fc60  IV=db21b75dac1a70bb2de1ef73ed9398ef
    #3 @DSD+0x21DB  salt=6af5082799d65c0e  IV=8f0428663981b85c954ecee20a23b059

  关键点：全文没有 RSA 公钥、没有 X.509 证书、没有 signature 字段。
  所以它不验证任何东西 —— 它是"用口令加密的数据"。

二、那么"跨设备能不能用"？—— 只有一个回答：必须实测
------------------------------------------------------------------------
  能确定的部分：
    · 密文是逐台的（salt/IV/密文都不同）—— 这点没疑问
    · 但它是不是"绑死在这台设备"（比如口令 = 本机 MAC/序列号/OTP 密钥），
      静态分析看不出来 —— 没有口令就无法判断能否解开

  两种可能，后果完全不同：
    (a) 口令是工厂统一密钥  ->  别的设备刷了能解开，能正常用
    (b) 口令含设备唯一信息  ->  别的设备解不开，等于空数据

  我倾向于"必须实测"，因为 Airoha 这类 SDK 两种做法都见过。

三、实测方法（不改硬件，5 分钟）
------------------------------------------------------------------------
  准备：A 机（有原厂 DSD）、B 机（砖机）

  1) 备份 B 机现有 DSD（如果能读）
  2) 把 A 机的 DSD 整段写到 B 机的 0x400000
  3) 开机，看串口：
       - 出现 WiFi 校准相关报错 / 校验失败  -> 属于 (b)，绑定设备
       - 无报错，WiFi 能起来               -> 属于 (a)，可以跨设备用
  4) 再用 /sys 或 iw 查一下 B 机 WiFi 的 MAC 和信道 TX 功率是否正常

  注意：这一步不改 MAC 时，两台机器会撞码，别接到同一个网络里。

四、对"修别人的机器"的实际结论
------------------------------------------------------------------------
  优先级从高到低：

  1. 对方有原厂备份          -> 直接用，什么都别改
  2. 能找到同型号正常机器
       -> 用完整版 GUI「载入现有 DSD」读那台的 DSD，只改
          wan_mac / lan_mac / serial_number，其余（含 0x1000 与 0x5000 段）
          原样保留，然后按第三节实测一次确认可用
  3. 什么都没有              -> 用无备份版生成（文本段 + 结构 + 尾部标记），
                               0x1000 / 0x5000 段为空。
                               预期：能开机、U-Boot 正常、有线正常；
                               WiFi 大概率能连但没校准，5G 可能不起来。
                               **这一段是唯一真正救不回来的东西。**

五、需要说明的一个诚实边界
------------------------------------------------------------------------
  我手上没有第二台 XR1710G，也没有原厂产线工具，
  所以"跨设备能不能用"这个问题我无法替你下结论 ——
  只能给你上面这个 5 分钟就能验证的实测方法。
  如果你测出来是 (a)，那 0x1000 段就可以放心复制；
  如果是 (b)，那就只能接受 WiFi 无校准，或者用产线工具重做。
